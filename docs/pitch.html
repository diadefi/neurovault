0:00–0:45. We are Darshan and Sebastian, building NeuroVault. A cold wallet protects authority by requiring deliberate signatures. Trading automation needs to react while its owner is away. Existing conditional orders already solve basic stop execution, so we are not claiming to invent signature-free stops. We explore a narrower question: can an adaptive volatility rule run inside the contract, while the caller has no withdrawal authority? The risk we want to reduce is broad owner permission living in a bot. This prototype demonstrates that boundary on Arc Testnet.

0:45–1:30. The owner authorizes neuron settings and opens the position. After setup, anyone can call poke. The caller does not supply a price or a destination. The contract reads the oracle, measures the absolute return, and feeds three leaky integrate-and-fire neurons. Their thresholds select a target trail from two to eight percent. The crucial rule is the ratchet: a long stop can rise or stay unchanged, but cannot fall. More volatility can slow further tightening; it never loosens a stop already established. Setup currently uses several transactions. There is no trained model and no price prediction.

Bound the caller’s authority.

  • Settings, opening and closing: owner only.
  • Long stops rise; short stops fall.
  • poke() accepts no price or recipient.

2:30–3:20. This is the security claim we can support: a permissionless caller cannot choose a withdrawal recipient, change owner parameters or lower an active long stop. The current suite has thirty Solidity tests, expanded from the initial twenty-one. It includes two fuzz tests with two hundred fifty-six sampled paths each. That is testing, not a proof or an audit. An agent can be the keeper.
Its authority should stay small.

Comparison is to broadly authorized agents, not all agent wallets. Session keys, spending limits and smart-account policies can also constrain agents. NeuroVault does not claim exclusive ownership of constrained automation.

3:20–4:10. This comparison is about authority, not a claim that every agent wallet is unsafe. An agent with broad permissions can choose many actions, which is useful but increases what a compromised agent can do. NeuroVault puts this particular risk rule inside the contract. The caller pays gas and triggers evaluation; it cannot choose the result or withdrawal destination. Modern agent wallets can also use session keys, spending limits and smart-account policies. These approaches can work together: an agent could operate our keeper. Our contribution is a small, inspectable adaptive-stop policy, with less flexibility and explicit oracle and liveness dependencies.
